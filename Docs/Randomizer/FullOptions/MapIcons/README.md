# Native VARIA map icons — rendering checkpoint

The development candidate draws original VARIA portal and colored-door sprites directly on the native pause map and minimap. This is part of the full randomizer integration, which remains incomplete. It does not add a separate tracker map or replace the original map UI. The local future-launch package remains at DoorColors; only isolated gaming-pc binaries were replaced for validation.

## Source assets and behavior

`Scripts/build-map-icons.py` reads the pinned VARIA source at `72ec1f30b700442d0c30aad6c43801bd64f1e2a5`. It compiles 48 original 8×8 sprites, 50 mapped colored-door identities, 32 area endpoints and eight boss endpoints into `Native/sm_map_icons.inc`. The immutable boss, area and door routing catalogs are unchanged. `audit.json` records source hashes, coordinates, original sprite words, palette colors and decoded pixels.

The artwork is `map/pause_extra.gfx`, loaded by VARIA's `VARIA_init` at VRAM word `$2CB0`, corresponding to OBJ indices `$CB..$FF`. Palette entries come from `pause_palettes.asm` and the referenced color constants. Sprite offsets, horizontal/vertical flips and words are checked against `mapicon_sprites.asm`. An initial extraction incorrectly read the older `pause.gfx` tile contents; visual inspection caught it before validation and the corrected extra-graphics source is the tested candidate's input. `original-sprites.png` shows the corrected source pixels at integer scale.

`sm_map_icons.c` composites these pixels into the same native 256-pixel and widescreen 400-pixel GUI buffers as the existing map. It respects PPU brightness and clipping, keeps the occupied minimap cell available for Samus's cursor, and draws before the existing logical check markers. Map/equipment navigation remains native. No graphics are generated by AI or interpolated.

Door icons use the committed door requirements and disappear once their saved door bit is set. Without door-color randomization, the renderer reads the actual restored PLM color. Blue doors and the eight nonrandom save/refill identities have no colored marker. The seed's committed area and boss mappings select portal colors and boss letters; pending or rejected world changes cannot alter them.

The visibility rules follow VARIA's `draw_portal_icons`: an unexplored source can display an unknown gray portal when the map is known; a destination color/letter is shown only when the source display tile and the destination's actual tile are both explored. An explored source whose destination remains unexplored has no portal icon. Project SM's existing fully-known randomized map acts as map knowledge, without granting exploration. Rendering never changes exploration, inventory, room state or save RAM.

## Validation

Native, Unreal Game and Unreal Editor builds pass. `Scripts/test-native-map-icons.py` passes 3,394 comparisons covering all 400 mapped-door/color cases, all 1,024 directed area pairs, 32 directed boss pairs, unknown/known visibility, clipping, native/wide minimaps, protected player cursor, combined worlds, original door requirements and unchanged Vanilla rendering. Every comparison checks the native pixels and both GUI buffers against source-asset pixels and checks that the renderer did not mutate gameplay RAM. These are controlled RAM fixtures, not manual traversal.

`Scripts/test-map-icon-regressions.py` passes the existing live tracker/native-pixel suite and an A/B/C bank containing ordinary area and combined area/boss/color plans, including later saves, reload, copy/clear and transaction rollback. This establishes that the extra drawing preserves the existing check colors and slot state; the previous increment's six seed/600-step solver results are not claimed as newly rerun here.

The actual Vulkan pause fixture uses generated seed 15092602 and deliberately marks all map bits explored for visual inspection. Native map/equipment navigation and resume pass with zero emulated CPU opcodes; the capture shows the original map with the new source-faithful symbols. This artificial reveal is confined to `SMTests` and does not validate natural portal discovery. A second Vulkan run uses a fresh map with no artificial exploration; its inspected capture shows gray portals without destination colors, and pause/navigation/resume also pass. The first uncapped run exposed a test-clock mismatch: its UI-frame schedule outran the fixed-rate native simulation. The passing invocation uses the same `-ExecCmds="t.MaxFPS 60"` as the normal launcher; no gameplay timing change was made.

Continue with the native counterpart of `writeExploreMapAsm`, current/saved-map synchronization and VARIA map counting. Normal exploration also needs VARIA's nonempty-tile and special-slope behavior. Preserve old saves and distinguish previously explored tiles when introducing counters. The counter span is inside the native snapshot's 64-byte door array: keep the live oracle's actual door requirements distinct from exploration counters. Rebuild/reselect complete map knowledge when world map data changes across slots.

Further map parity includes original boss-icon replacement/objective icons as general objectives become available.
