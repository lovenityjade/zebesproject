# Complete seed editor increment — 2026-09-15

The separate [Save Refill release](../../../../Releases/2026-09-15-save-refill/README.md) was frozen before this work. It is a local runnable release with source checkpoint and verification; it has not been published externally.

This increment exposes the audited non-cosmetic randomizer form in the existing English ImGui system menu. **It is not full native VARIA parity.** Unsupported world, endgame and patch behaviors remain rejected instead of producing misleading playable seeds.

## Editor

Nine pages: Seed & presets, Logic & difficulty, Progression, Items & ammo, World & escape, Goals & victory, Gameplay patches, Techniques, Combat & heat. The embedded catalog has 54 primary gameplay fields, 10 random-choice companion lists, 57 selectable goals with upstream exclusions, 27 patch sub-options, 105 techniques in eight categories, 10 combat/heat/hard-room tolerances, the 46 settings presets visible in the audited website and 11 bundled skill presets. Seed number, basic skill selection, local JSON import/export, No Advanced Techs and tablet quotas are additional controls. There is no runtime website dependency or PopTracker pack dependency.

The catalog is generated by `Scripts/build-seed-menu-catalog.py` from the pinned inventory and local upstream objective definitions. It contains no preset passwords/account metadata. Technique descriptions, goals and patch labels are taken from the source material. Basic skill indices preserve old Casual/Regular/Veteran settings. New choices extend those indices.

Random choices preserve their allowed lists in the request; a deterministic options RNG resolves values for the generator, fresh solver and tracker. Requested and effective settings are stored separately. `speedrun`/`basic` normalize placement difficulty to `normal`, following VARIA; the manifest records this adjustment. No Advanced Techs shows its effective disabled techniques/heat rules while preserving custom overrides for later use.

Fixed goals enforce mutual exclusions and boss/miniboss count limits in the editor. Scavenger, area, door, minimizer and random-objective dependent controls are disabled while their parent setting is off. This is only the editor dependency layer: complete upstream world/goal normalization and native behavior are still outstanding.

Local export writes the complete Project SM generation request, including the seed, skill, all option overrides, techniques, tolerances and relic quotas. Import accepts that request, a VARIA settings preset or a skill preset containing `Knows`/`Settings`. Known presentation/account/controller metadata is not applied to seed gameplay; malformed or unknown gameplay values are rejected before replacing the draft. There is no network preset submission.

## Persistence and generation

`FSMSeedRequest` now carries value-owned `OptionsJson`, `TechniquesJson` and `SkillSettingsJson`. Pending A/B/C slot metadata, copying, configuration persistence, generation, ready-seed reload and JSON export preserve these objects. Ready seeds remain immutable. Publication compares the full requested objects against the on-disk slot again, so a generation result cannot overwrite a draft changed in the meantime.

Generation still starts exclusively through **Generate Game** in the native new-file menu; Start Game remains gated by successful verified publication. The system UI edits the request. Updated native capability checks prevent a new UI binary from silently using an older core without the requested behavior.

## Native behavior added or connected in this increment

- Full/FullWithHUD/Major/Chozo pools, ammo density and weights, energy quantity, progression/difficulty/Morph/suit restriction, challenge removal categories, custom techniques and tolerances reach generation and live logic rather than fixed UI text.
- `Hide items` uses VARIA's randomized eligible visible-to-hidden carrier conversion. The original pickup scripts, reveal behavior, location bits and item grants are retained. Native validation allows this conversion only at the pinned eligible locations; switching plans restores vanilla words before reapplying another plan. Tracker metadata distinguishes original and effective visibility.
- `Fast doors` runs the original scrolling routine twice per IRQ, stops when the first call finishes, and aligns the camera by up to two pixels with correct odd-distance endpoints. This ports the gameplay changes in `fast_doors.asm`; native decompression already runs as C.
- `Ultra sparse` now carries the actual native equivalent of `nerfed_rainbow_beam.asm`: 20 drain frames instead of 300, doing 20 damage with Varia or 40 without it. Generation still rejects a pool if combat or progression cannot meet the requested difficulty.
- `Refill before saving` is a per-seed request as well as the independent optional global comfort setting. The accepted save-station confirmation refills energy, reserve energy and all three ammo pools before SRAM capture. Global comfort enablement can also provide this behavior in Vanilla.
- HUD, improved reserves and revealed map can be disabled per seed. New port defaults are On to match the presentation previously requested for randomized games. The versioned `seed-interface-v1` behavior tag protects historical seeds from suddenly interpreting their old upstream defaults as new presentation choices. Map display does not mark exploration as completed.

The subsequent [ElevatorsHud increment](../ElevatorsHud/README.md) implements exact Full/Major/Chozo/FullWithHUD count lists and fast elevators. Ordered Scavenger and general objective HUD semantics still require further work.

## Verification and limits

All runtime checks ran in the marked isolated directory on **gaming-pc**. The local user game was not launched or restarted, and no actual user SRAM was edited.

- Six seeds exercise custom ammo/technique/heat rules, Major split, allowed random pools, challenge removal, hidden pickups/interface-off choices and ultra-sparse energy/fast doors. Every accepted seed has 100 reachable checks and a verified completion route. Spoiler items agree with the fresh progression log. Repeating the first request after the other contexts produces the same fingerprint.
- Actual native item plans stage, initialize, switch back to vanilla and reapply for all six seeds. Original ROM bytes remain unchanged on disk.
- Thirty in-process live tracker queries replay inventories from five progression steps per seed. Green checks stay within the effective difficulty and enabled techniques. This tests the actual oracle, not merely the serialized preset.
- Native routine probes cover original/randomized modes, eight behavior masks, 192 camera alignment cases, door completion including the last-step guard, HUD/reserve/map gating and 32 rainbow-drain cases. The probes call the actual compiled routines in an initialized game using symbols from the exact test library. They are controlled native logic fixtures, not full rendered door traversals or complete boss playthroughs. Emulated CPU opcode count stays zero.
- Unreal profile tests cover independent drafts, copy, complete JSON reload, malformed settings, stale generation rejection, publication, ready-seed immutability, historical profiles and existing tablet quotas.
- Offscreen Unreal captures cover all nine pages and the expanded objective editor. These verify rendering; they are not a full manual mouse/controller pass over every control.

Proof files and final build hashes are alongside this document. Failures encountered while developing the fixtures are not counted as passes; the final verification files identify the accepted results.

## Still outstanding

Area/boss/door topology; mirror world; Minimizer; Scavenger's ordered collection and finish rules; the 57 general objective evaluators and their persistent state; alternate Tourian/escape behavior; race handling; remaining individual layout/tweak and gameplay patches (including respin, Speedkeep, suit behavior, weakened Charge and Crystal Flash). Their solver, native state, tracker, counters and UI must agree before they can be advertised as supported. The later [Starts increment](../Starts/README.md) integrates the 13 starts available without area randomization; the two area-only starts still depend on that remaining work.

The remaining work is substantial. Exposing the complete form does not mark the broader request complete.
